# Testing

| Suite | Location | What it covers | Needs |
|-------|----------|----------------|-------|
| Unit | `backend/tests/SkyJourney.UnitTests` | Domain rules (money, DST, schedules, booking state machine, refunds), validators, pricing, the demo data set | .NET 10 SDK |
| Integration | `backend/tests/SkyJourney.IntegrationTests` | The real API hosted in memory (`WebApplicationFactory`) against a throwaway PostgreSQL 17 container (Testcontainers) | .NET 10 SDK + a running Docker engine |
| Mobile | `mobile/SkyJourney.Mobile` | Type checking, lint, component/unit tests (jest-expo) | Node 22 |

## Running

```bash
cd backend
dotnet test                                           # everything
dotnet test --project tests/SkyJourney.UnitTests      # unit tests only, no Docker
dotnet test --project tests/SkyJourney.IntegrationTests
```

Both test projects use **xUnit v3 on Microsoft Testing Platform**. `backend/global.json` opts the
`dotnet test` command into MTP, which the .NET 10 SDK requires for xUnit v3.

### Integration-test conventions
- One PostgreSQL container per test run (an xUnit *assembly fixture*: `SkyJourneyApiFactory`). Migrations
  and demo seeding run exactly as they do in development.
- The clock is a `FakeTimeProvider` frozen at **2026-11-02 06:00 UTC**, and the seed horizon is 21 days, so
  flights, prices and sales-cutoff behaviour are identical on every run and every machine.
- Tests that change data (sold-out flights, cancellations) use their own route and date, so they don't
  interfere with other tests that run in parallel.
- Auth tests register a unique `user-<guid>@example.com` per test. Tests that move time forward (token expiry)
  or need different settings (rate limits) start a second in-memory host on the same database with its own
  `FakeTimeProvider` (`factory.WithOwnClock(...)`), so the shared frozen clock never changes.
- Booking tests each use their own route/date (listed in `BookingTests`). Concurrency tests fire parallel requests
  through the real HTTP pipeline at the real database: 10 users racing for the last 3 seats (exactly 3 succeed),
  6 users racing for one seat (exactly 1 succeeds), 8 retries with one idempotency key (one booking).
  The hold-expiry test uses its own clock and signs in again after advancing it, because the hold (20 min) outlives the
  access token (15 min).
- Payment tests (`PaymentTests`) cover outcomes per test token, replay and key reuse, 8 parallel payments with different
  keys (exactly one charge), 6 parallel retries with one key (one attempt), paying after the hold lapsed (own clock), and
  the per-user payment rate limit (own host with a limit of 2).
- Background jobs are disabled in tests (`BackgroundJobs:Enabled=false`). `JobTests` resolves the job from the host's
  hosted services and calls `RunOnceAsync`. The expiry test moves only its own booking's `expires_at` into the past, so the
  shared clock stays frozen; the horizon test uses its own clock one day ahead and checks flights appear on day 22 only.
- The shared host raises the auth and payment rate limits, because every in-memory request comes from the same "client IP".

### Mobile

```bash
cd mobile/SkyJourney.Mobile
npm run typecheck   # regenerates Expo Router's typed routes (.expo/types, git-ignored), then runs tsc
npm run lint
npm test
npx expo-doctor
```

`npm run typecheck` runs `expo customize tsconfig.json` first, because typed routes are otherwise only generated by a
running `expo start` (and not at all when Metro runs with `CI=1`). Without that step a fresh checkout fails to type-check
any link to a route added since the types were last generated.

Mobile test conventions:
- Logic that matters (the session manager, criteria validation, sorting) is plain TypeScript with injected dependencies,
  so it is tested without rendering. `createSessionManager` takes an `api` and a `storage` object; tests pass
  in-memory fakes and use deferred promises to drive races such as concurrent refreshes.
- Screen tests render the real screen inside the real providers and mock only `expo-router` and native modules
  (`expo-secure-store`).
- jest-expo replaces the global `fetch` with a stub, so jest tests can't reach a running API. Live checks against the
  local API are manual (see the implementation log), and E2E is covered in M20.

### Docker via Colima (macOS)
Testcontainers starts a helper container (Ryuk) that mounts the Docker socket. With Colima, the
host-side socket path can't be mounted into the VM, and the error is
`invalid mount config for type "bind": stat …/.colima/docker.sock: operation not supported`.
Point Testcontainers at the socket path *inside* the VM:

```bash
export TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock
```

Docker Desktop and Linux CI runners don't need this.
